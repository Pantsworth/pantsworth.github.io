# pantsworth.github.io — working notes for Claude

Michael Nowakowski's personal site (**nowakowski-studios.com**), served by **GitHub Pages**
from this repo's default branch (`.nojekyll` — files served as-is; `CNAME` sets the domain).

## Build

Static site generated by `generate_site.py`: it renders `templates/*.html` (Jinja) into
**root-level `*.html`** and optimizes images. Deps aren't fully in `requirements.txt` (it
needs Pillow), so run with `uv`:

```sh
uv run --with pillow --with jinja2 python generate_site.py
```

**The generated root `*.html` are committed and served.** Always edit the **`templates/`**
(and `css/`, `js/`), then rebuild — never hand-edit the root `*.html` (they're overwritten).

### How templating works
- `templates/base.html` is the shared layout (nav, `<head>`, footer, theme + toggle JS).
  The build **skips** it; every page `{% extends "base.html" %}` and overrides the
  `head` / `body` / `scripts` blocks (each calls `{{ super() }}` first).
- Each render gets `name` = the template filename minus `.html` (used for the active-nav
  indicator and page title).
- `generate_site.py` has per-file branches: `photos.html` gets `album_config`,
  `projection_design.html` gets `projection_design_config`, `index.html` gets `images`
  (legacy — the landing no longer uses it); everything else just gets `name`.

### Templated pages vs. standalone
- **Templated** (regenerated by the build): `index` (landing/bio), `work` (résumé),
  `software`, `photos`, `videos`, `projection_design`, `about` (redirect → index).
- **Hand-maintained, NOT templated** (no `templates/` source): `CHEF.html`,
  `recipes.html`, `machine_learning.html`, `pano-demo.html`, `404.html`. These have their
  own `<head>`/nav and are off the main nav — edit them directly if needed.

## Navigation
Nav lives in `base.html`: **About** (→ `index.html`) · **Work** · **Software** · **Photos**
· **Videos**. Brand ("Michael Nowakowski") → `index.html`. Projection Design is intentionally
**off the nav** (page kept, reachable by direct URL only). The current page's nav link gets
`.active` (white + underline). A theme-toggle button (☾/☀) sits at the far left of the nav.

## Theming (light/dark)
- Colors are **CSS variables** in `css/gallery.css` (`--bg`, `--fg`, `--muted`, `--strong`,
  `--rule`, `--link`, `--card-bg`, `--card-border`, `--overlay`, `--navbar-bg`,
  `--navbar-border`). Add new colors as variables, not hardcoded values.
- **Dark = true black** (`#000`). Applied automatically via
  `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` **and** manually
  via `:root[data-theme="dark"]` (keep both blocks in sync).
- Manual toggle: the navbar button sets `data-theme` on `<html>` + saves to `localStorage`.
  A tiny inline script in `<head>` applies the saved theme before paint (no flash).
- In dark mode the navbar stays true black but gets a `2px` white bottom border
  (`--navbar-border`) to separate it from the page.

## Fonts
The site uses **browser-default (system) fonts** — no web fonts are loaded (Monoton /
Permanent Marker were removed). Headings are bold; the navbar/brand are italic. Note:
`.marker-text` is now just a bold class (legacy name — it no longer applies a marker font).

## Photos gallery (`templates/photos.html`)
- **Flex-column masonry**: JS builds N flex columns (tops always align) and drops each image
  into the currently-shortest column (balanced bottoms). Responsive 4→2→1 columns; it probes
  thumbnail aspect ratios to balance, so an album paints once its thumbs load. (CSS
  multi-column was tried and abandoned — it clipped shadows and misaligned tops.)
- **Album tabs** are a navbar-style secondary nav (italic, underline-active) — not buttons.
- **Deep linking**: `photos.html?album=places` opens that album (case-insensitive); clicking
  a tab updates the URL via `replaceState`.
- **Panoramas** render as a single full-width column with a "View in AR" badge on AR-capable
  Apple devices (`js/pano-ar.js` builds a curved-screen USDZ from the `_ar` texture).
- Lightbox is **simple-lightbox** (jQuery). The landing headshot also opens a lightbox.

## Images
Source images live in `img/flickr/<section>/<album>/`; the build writes optimized copies to
`img/flickr_optimized/...`:
- `<name>.jpg` (≤3000px), `<name>_thumb.jpg` (≤800px, used in galleries), and for anything
  under `/panoramas/`, `<name>_ar.jpg` (≤4096px, used by the in-browser USDZ builder).
- **To add photos**: drop them in the right `img/flickr/still/<album>/` folder and rebuild.
- **Albums shown on Photos** = keys of `album_config` in `generate_site.py`
  (Places, Panoramas, Illustrative, Portraits, Performances; Experiments is commented out).
  To add/rename an album, edit `album_config` (and the matching folder).
- Non-gallery images (project screenshots, headshot) live directly under `img/…` and are
  referenced as-is.

## Frameworks
Bootstrap **4.3.1** (CSS + JS), jQuery 3.5, simple-lightbox — all from `node_modules/`,
loaded in `base.html`. Bootstrap is still used for the navbar/collapse, grid
(`container`/`row`/`col-*`), cards (Videos page), and a few utilities; most visual styling is
custom in `css/gallery.css`.

## Résumé / LLM files
- `work.html` is the human résumé; `files/michael-nowakowski-resume.pdf` is a **snapshot**
  copied from the `job_hunt` repo's compiled résumé — re-copy it when the résumé changes
  (and it must be explicitly `git add`ed; it's untracked by default).
- `resume-long.md` (site root, machine-generated long-form résumé) and `llms.txt` exist for
  LLMs/agents; `base.html` points to them via a `<link rel="alternate">`, an HTML comment,
  and a footer note (the footer is visible only on `index`/`work`, hidden elsewhere).

## Conventions
- Edit templates → rebuild → commit **both** the templates and the regenerated root `*.html`
  (plus any new `img/flickr_optimized/*` assets). `.venv/` is gitignored.
- Per the owner's global rules: don't run git commits/other git ops without checking first.
